# Linthra v0.2.5

Linthra 0.2.5 is the desktop release. It turns the Linux build from a phone layout stretched across a monitor into something that behaves like a desktop music player: a persistent navigation shell, layouts that adapt to the width they are actually given, and a window that finally identifies itself correctly to the desktop. Android gets a clearer local-music story, an Android Auto fix for large libraries, and more honest Jellyfin connection state.

## What's new

- **Persistent desktop navigation.** Wide Linux windows get a navigation rail that stays put beside the content instead of a bottom bar. Each destination keeps its own stack, so switching tabs and coming back lands where you left off. Keyboard traversal reads the rail as one group rather than interleaving it with the page.
- **Layouts adapt to the window, not to the platform.** Breakpoints are driven by the width a view is actually given, so a screen inside the rail measures the space it really has. Everything below 600 px is unchanged from the phone layout.
- **Denser album and artist grids.** Album cards stay between 200 and 260 px and the grid adds columns instead of inflating covers: 5 across at 1280, 7 at 1920, 10 at 2560. Artists flow into 2 to 5 columns instead of one row per monitor width.
- **Album and artist detail get a side pane.** At expanded widths the cover or portrait, the counts, and Play/Shuffle sit in a persistent left pane beside the scrolling track list. Selection mode falls back to the single column.
- **Now Playing and lyrics use the whole window.** The cover sits beside the metadata and transport at expanded widths, and lyrics open next to the cover instead of replacing it, sharing the same toggle and playback state.
- **Single-column views stop stretching.** Songs, playlists, downloads and settings cap and centre their column, so a title and its trailing action never end up a screen apart.
- **Resizing preserves state.** Crossing a breakpoint moves the navigation without rebuilding it, and inactive branch stacks survive the resize.
- **Transport controls on the now-playing bar.** When the bar has room it carries favorite, previous, play/pause, next and a queue button. Previous and next follow the live queue and grey out at its ends. It is the same widget on a phone, so it sheds controls as the window narrows and below 360 px it is the bar we had before.
- **Folders is a top-level destination.** It moved out of the Library tab strip and sits next to Library, Playlists, Downloads and Settings, so the folder trail survives a trip to another tab.
- **The Linux window identifies itself correctly.** WM_CLASS now matches the app id exactly, the desktop entry declares the same pair as `StartupWMClass`, and the window carries a real icon, so launchers and task switchers group and draw Linthra instead of falling back to a generic entry.
- **Music folders open through the desktop portal on Linux.** The runner registers its own folder picker backed by `GtkFileChooserNative`, which draws in process on a native build and routes to `xdg-desktop-portal` inside the sandbox. One code path serves both, and the Flatpak still ships without host filesystem access.
- **Credentials go to the platform keyring inside the Flatpak.** Provider credentials use the Secret Service through one narrow D-Bus grant (`--talk-name=org.freedesktop.secrets`), rather than a session-bus socket or a wildcard.
- **Configured servers reach the network from the Flatpak.** The sandbox now permits the networking a configured server needs, and the finish-args parser handles quoted and commented entries correctly.
- **Device-wide music access on Android is explicit.** Choosing your whole device library is now its own visible choice, separate from picking a folder, with its own permission flow and its own empty-state and error wording. Switching is transactional: a denied permission or a failed first scan leaves the previous folder and the indexed catalog exactly as they were.
- **Android Auto no longer spins on the Songs list.** Songs is served in bounded browse pages, so large libraries load instead of overrunning the media browser's transaction buffer and never returning.
- **Jellyfin connection state is real.** Configuration and reachability are tracked separately, so a LAN-only server you are away from reports as unavailable instead of "connected" while every stream fails. The catalog, playlists, favourites and downloads stay put.
- **AppStream metainfo for software centres.** Linthra ships an AppStream component so Linux software centres can describe and list it.

## Linux and Flatpak status

The GitHub Release still publishes the native Linux x64 archive:

`Linthra-v0.2.5-linux-x64.tar.gz`

Flatpak packaging in this repository is now building end to end on clean runners, with sandbox coverage for filesystem access and offline sources. Linthra is **not** published on Flathub yet, and this release does not claim a Flathub submission.

The desktop work above is validated on the native Linux build and the packaged Flatpak. Runtime requirements and the current Linux support matrix are documented in `docs/linux-desktop.md`.

## Android and F-Droid

Android remains a first-class target. The canonical Android version for this release is:

- versionName: `0.2.5`
- base versionCode: `205999`

F-Droid's split-ABI scheme remains:

- armeabi-v7a: `2059991`
- arm64-v8a: `2059992`
- x86_64: `2059993`

GitHub APKs and F-Droid packages remain signed by different keys, so users should keep updating from the same install source they originally chose.

Linthra is **not** publicly available on Google Play. CI can publish signed builds to a Google Play testing track; that is a distribution pipeline, not a public listing.

## Licensing

This is the first release cut after the relicensing to **AGPL-3.0-or-later** (#535). Releases up to and including v0.2.4 remain under the MPL-2.0 terms they were published under, and that text is preserved at `docs/licenses/MPL-2.0.txt`. See `docs/license-transition.md`.

The F-Droid metadata in this repository still declares `License: MPL-2.0` because its `Builds` entries all point at pre-transition source commits. Switching that field is an fdroiddata-side step, documented in `docs/fdroid-submission.md` §9, and is not part of this release bump.

## Upgrade notes

No manual migration is required. Existing Android library and settings data remain in place during a normal same-source update, and Linux users can replace the previous native archive with the new one.

Android users who previously pointed Linthra at a folder keep that folder. Device-wide music access is an opt-in choice, not a default.
