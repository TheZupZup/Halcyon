# Linthra v0.2.4

Linthra 0.2.4 adds Android build-provenance protection so users can tell when an APK is outside the official Linthra signing identity.

## Build integrity

- Android reads the installed APK's current signing certificate locally through `PackageManager` and hashes the public certificate with SHA-256.
- The expected fingerprint is the same developer certificate already pinned by F-Droid through `AllowedAPKSigningKeys` for Linthra's reproducible-build flow.
- A recognized release certificate is shown as **Official signed build** in Settings → About.
- An unknown release signature shows a full-screen **UNOFFICIAL LINTHRA BUILD** warning before the normal app UI and remains visibly marked in Settings → About.
- If Android cannot verify the signing identity, Linthra fails closed and shows the same provenance warning rather than silently claiming the build is official.
- Local/debug builds are classified as development builds so normal contributor and CI workflows are not interrupted.

The warning does not claim that every unknown APK is malicious. It says only what Linthra can prove: that the package is not inside the project's verified release-signing identity. Users are specifically warned not to enter server credentials unless they trust where that build came from.

## Why

Open-source software can legitimately be forked and rebuilt, but a modified APK can also keep the same package name and visual identity. The goal here is to make that origin difference obvious to users and reduce the chance that a repackaged or malicious build is mistaken for an official Linthra release.

This technical check complements the separate branding/trademark policy and planned stronger-copyleft licensing transition. It does not make an open-source client tamper-proof: a determined fork can remove its own warning code, which is why signing, branding, source-license obligations, and official distribution documentation are separate layers.

## License transition status

The repository is still MPL-2.0 while the AGPL-3.0-or-later relicensing audit and contributor permissions are being completed. Historical releases keep the license under which they were published; the license file and active metadata must not be switched early just because the provenance feature is ready.
